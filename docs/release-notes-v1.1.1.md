# Observer v1.1.1 发布说明

## 修复 Claude 思考用量的细分与费用

- 修复原生 Claude 同步与流式请求出现“总 Token 有值、细分不完整、费用 $0”的问题：
  CPA 的原始输出计数已经包含思考，但原生插件桥没有传递标准化细分，
  旧逻辑重建时再次加入思考，导致守恒校验失败并清空可计费的细分桶。
- 只对原生 `claude` provider、`ClaudeExecutor` 或未带执行器名称的回调适配。
  原始计数必须非负，思考不能超过输出，缓存桶必须明确，且正的显式 total
  必须严格等于“未缓存输入 + 缓存读 + 缓存写 + 已含思考的输出”。
- 恢复后的思考仍是输出子集，同价时不重复收费，独立定价时按子集拆账；
  费用、Key 额度累计和汇总使用同一份标准化细分，`raw_usage` 原样保留。
- 已完整的独立思考计数保持兼容；自定义 provider、OpenAI 兼容执行器、
  无效计数和不守恒总量不会被强行修成完整，也不会按总 Token 猜测费用。
- 补充计数守恒与异常边界回归，以及真实 CPA 宿主下 Claude 同步/SSE 的用量、
  费用、额度扣减与耗尽拒绝测试。

## 最新 CPA SDK 适配

- SDK 升级至 `CLIProxyAPI/v8 v8.0.53`，与最新正式宿主对齐。
- 同步 CPA 锁定的 `moego` JSON 实现，移除 SDK 已不再使用的旧 JSON 间接依赖。
- 最低宿主仍为 CPA **v8.0.30 / 插件 schema 6**，不启用新增正文省略/修改能力；
  不修改 CPA 核心、请求正文/头、模型路由、重试或会话。

## 升级边界

- 本版继续使用 **schema3 / `observer_features=4`**，从 v1.1.0 升级无需重建数据库。
  从 v1.0.0–v1.0.4 或更早版本升级时，仍须遵守 v1.1.0 的备份与回退边界。
- **修复只影响升级后的新入账请求。** 已保存的零费用、历史汇总和 Key 额度不重算，
  不补造费用，也不产生持久 Key 封锁或人工恢复要求。
- 升级前请停流、正常停止 CPA，并备份整个数据目录及匹配的旧插件二进制；
  数据库含可用客户端密钥明文，应按凭据资料保护。升级后刷新管理页面。
- 发布不等于生产部署，不会自动修改生产配置、数据库或宿主二进制。
