# Observer v1.1.0 发布说明

## 最新 CPA SDK

- SDK 从 `CLIProxyAPI/v8 v8.0.30` 升级到最新稳定版 `v8.0.47`，同步上游要求的间接依赖。
- 手工构建最低 Go 版本提高到 **1.26.10**；预编译发行包的使用者不需要安装 Go 或 Node。
- 最低宿主仍为 CPA **v8.0.30 / 插件 schema 6**，CI 同时验证该基线和最新稳定 v8。
- 保留非独占认证与现有 schema 6 能力声明，不启用新版正文省略或正文修改能力。
  不修改 CPA 核心、请求正文/头、模型路由、重试或会话。

## 请求体条件定价

- 手工价格覆盖和倍率规则支持 `requestBody: {"path":"/speed","equals":"fast"}`，
  可与 `all/any/not` 等既有条件组合；覆盖与倍率的应用顺序、`serviceTier` 语义不变。
- `path` 使用 RFC 6901 JSON Pointer，`equals` 仅接受字符串、数字、布尔或显式 `null`。
  数字采用精确十进制比较，不经过二进制浮点，`2` 与 `2.0` 相等，大整数不会被静默舍入。
- 设置页提供路径、类型和值编辑，保存与重载保留数字精度；数字条件需要浏览器支持
  `JSON.rawJSON` 和 `JSON.parse` reviver `context.source`，不支持时明确报错。
- 求值对象为 `request.intercept_before` 收到的协议翻译前请求体。路径缺失、实际值非标量
  或路径穿过标量为不匹配；显式 `null` 不匹配缺失字段。正文缺失、非法、超限或没有可关联
  快照时条件未知，缺少完成报价所需事实时仍按现有规则以 $0 入账，不阻断后续请求。
- 只为手工价格规则收集最多 128 个条件，正文解析上限 32MiB。按 Key+Trace 关联，
  有界保留条件 SHA-256 指纹与布尔匹配结果；不为计费保留字段值、正文、消息或请求头，
  不把这些原始数据写入账本。诊断采集仍是独立的显式开关。
- **请求字段由客户端控制，可能据此选择较低价格。** 不应将它视作可信上游计费事实。
  改价只影响未来请求，不重算已保存的费用、报价或额度累计。

## models.dev v2 目录兼容

- 完整跳过包含 `region` 条件的有效倍率规则，并保留 `region_multiplier_ignored` 诊断；
  不只删除条件分支后套用本不该生效的倍率。
- 保留可用基础价、缓存 TTL、其他覆盖和倍率顺序；非法条件、深度/节点上限及非法倍率
  仍严格校验，不以忽略 region 为由接受错误价格定义。

## 升级与回退边界

本版仍使用 **schema3**，数据库能力标记提高为 **`observer_features=4`**。
从 v1.0.0–v1.0.4 升级无需重建数据库，已有 Key、价格配置和历史金额保留；
**新版打开数据库即会写入 feature 4，即使未配置请求体规则，旧版也不能直接打开该库。**

升级前请停流、正常停止 CPA，并备份整个数据目录及匹配的旧插件二进制。
数据库和备份含可用客户端密钥明文，应按凭据资料保护。
如需回退，必须恢复升级前的一致备份及匹配的旧二进制，不要只替换插件文件；
恢复旧备份会丢失升级后的数据，需提前保全。
schema2 及更早数据库继续在可写打开前被拒绝，不提供迁移或历史重新计价。

用量漏记、记账失败或异常重启仍不产生持久 Key 封锁，也不要求人工恢复；
认证、启停、模型权限、额度和并发限制继续独立执行。
CPA 非持久化用量队列仍可能在升级/崩溃时丢失尚未落盘的记录，不补造费用。

发行包覆盖 **Linux amd64、Linux arm64、macOS arm64**，附 `checksums.txt`。
Linux 包不适用于 musl/Alpine。升级插件后请刷新管理页面以加载新版内嵌前端。
发布不等于生产部署，不会自动修改生产配置或数据库。
