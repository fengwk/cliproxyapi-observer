# Observer v1.0.4 发布说明

## 可用性优先：删除记账异常封锁与人工恢复

- 记账写入失败、用量漏记、回调异常或 CPA / 容器异常退出，不再封锁 Key，也不要求管理员确认未知费用风险。
- 删除待记账重试队列、启动会话封锁、磁盘中断标记及其锁、回调故障闸门，不增加替代开关或其他恢复门槛。
- 删除 Key 列表的封锁状态、筛选和恢复弹窗；健康响应不再包含 `pending_usage`，Key 响应不再包含 `blocked_reason`。
- 删除 `POST /keys/recover` 管理接口，不保留兼容别名或空操作；调用已删除接口返回 404。
- 真实报价错误、费用溢出和用量写入错误仍报告脱敏诊断，但不影响后续请求准入。成功的缺价或缺少计价事实报价仍按原规则以 $0 入账。

## 账目与请求限制保持独立

- 已成功保存的金额、历史、冻结报价、Key 和配置不变；成功入账仍原子提交并去重，不重算历史。
- 缺失的记录保持缺失，不估算、不补造费用，也不在后台重建漏掉的执行。
- 认证、手动启停、撤销、删除、有效期、精确模型权限、额度和并发限制继续生效；数据库真正不可访问时，不会绕过这些必要检查。
- CPA 原生凭据仍由宿主管理；本版不修改 CPA 核心、模型路由、请求正文/头、上游选择、重试或会话。

## 升级边界

本版沿用 schema3 / `observer_features=3`。从 v1.0.0–v1.0.3 升级无需重建数据库；
旧库中的记账封锁字段、运行标记及库旁的旧中断文件不再参与准入判断，已有 Key 无需逐个恢复。
程序不扫描清除这些旧文件，也不会自动修改生产数据库或配置。schema2 及更早版本仍不兼容。

升级前请停流、正常停止 CPA，并备份包含客户端密钥明文的整个数据目录。
CPA 的用量队列不持久化，且没有可靠的热替换前排空保证；尚未落盘的用量可能丢失，
本版接受这种缺失，不承诺端到端恰好一次，也不会因此产生持久封锁。

安装新版插件并重新加载后，刷新管理页面以使用新版内嵌前端。发布不等于生产部署。
