# Observer v0.9.2 发布说明

## 请求调试与显示修复

- 请求头采集由 Content-Type/Accept/User-Agent 三项白名单扩展为非认证敏感头：
  保留自定义头、请求追踪头和多值头，继续排除 Authorization、Cookie、API Key、
  Token、Secret 等凭据字段，并对 URL 用户信息及敏感查询参数脱敏。
  采集的仍是认证前客户端请求头副本，不采集上游凭据，不修改实际请求。
- 保留请求头 16KiB 整组上限，名称、保留值及每值最小开销均受预算约束；
  超限整组不保存，不以截断片段冒充完整内容。采集仍默认关闭、异步有界，
  遵循原有管理鉴权、内容有效期与存储预算。
- 请求列表客户端 Key 列垂直居中，移除多余的内部 ID 复制按钮；
  Key 管理页的真实客户端密钥显示与复制能力保持不变。
- 请求列表、详情、分组和顶部摘要的耗时/TTFT 统一使用秒、保留两位小数，
  数值与单位不拆行；后端毫秒字段和 TPS 计算口径不变。
- 修复模型/Key 下拉在远端 facet 搜索开启时不执行本地过滤的问题。
  搜索支持大小写不敏感匹配；Enter 选择可见匹配项，不再误选“全部”清空筛选；
  无匹配时保留原选择，关闭时清理搜索而不重复请求。
- 趋势图时间标签移出非等比缩放 SVG，避免文字被横向拉伸。
  时间刻度随容器宽度自适应、保持 UTC，首末与绘图区对齐，窄屏减少刻度避免重叠。

## 自定义 provider 用量修复

修复 commandcode、opencode-go 等自定义 provider 的 SDK 用量细分被重新归为
unclassified 后丢失的问题。仅对未分类用量，在原始计数非负、有正的上报总量、
至少一个输入/输出计数为正且固定 SDK 构造器能给出唯一或一致的完整守恒结果时，
恢复标准化细分。不根据 provider 名称硬编码协议，不改变原始用量或模型/渠道身份。

缓存命中率仍为：缓存读 /（未缓存输入 + 缓存读 + 缓存写）。
恢复后的可信细分参与后续请求的缓存命中率、TPS、定价与汇总。
已知 provider 的 SDK 完整/不一致判断保持不变；只有总量、缺少总量、无法守恒、
溢出或无法解释旧缓存聚合字段的用量，继续保持不完整，不虚构缓存桶。

**不重算历史账单、额度或已保存的细分，不新增迁移。**
Observer 只能使用 CPA 已上报的计数，无法补回上游或协议转换中已经丢失的缓存字段；
例如 DeepSeek 原生缓存字段未被宿主识别时，仍需在对应解析链路解决。

## 兼容、隐私与升级

沿用 schema2、`observer_features=2` 和原数据库路径，SDK 仍锁定 CPA v8.0.30，
最低插件 schema 6。CPA 原生凭据及 Realtime 令牌与 Observer 非独占共存；
认证、模型授权、路由、重试和会话边界不变。没有 CPA 核心修改或 Go/npm 依赖升级。

**启用内容采集后，新请求会保存更多非认证敏感请求头。**
字段名过滤不能识别普通自定义值中的所有秘密，请妥善保护数据库、备份与管理端。
客户端 Key 明文仍保存在管理数据库中；升级/回退前安排停流并做一致备份，
详细步骤见 [v0.9.0 发布说明](release-notes-v0.9.0.md)。

发行平台仍为 Linux amd64、Linux arm64、macOS arm64。
下载后核对 `checksums.txt` 和归档内 `metadata.json`。
既有标签和公开资产不覆盖；发布不部署到生产、不修改生产配置或数据库。
