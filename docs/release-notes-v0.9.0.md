# Observer v0.9.0 发布说明

## 本版变化

- **当前客户端 Key 明文可持续查看和复制**：按内部管理需求，新建、自定义和轮换
  同时保存当前明文与认证哈希。列表和详情展示真实密钥，不再拿内部 ID 代替。
  关闭成功弹窗、刷新、重启后仍可查看；移除“一次性显示”提示。
- 保留稳定 Key ID、精确模型权限、事务性额度/记账和历史费用。禁用保留当前密钥，
  撤销和终态删除清除当前明文及哈希。重复密钥冲突不影响原密钥。
  不承诺擦除 bbolt 的历史页或已有备份。
- 修正“记住登录”原生复选框的对齐。移除设置页重复标题、跳转链接和空的嵌入头部，
  将退出放到设置页底部，保留未保存确认和管理凭据清理。
- 嵌入页签置顶，内容区独立滚动并避让宿主浮动操作；滚动条采用 CPA 原生样式，
  不修改宿主 DOM。保留不同宽度、主题、侧栏和原生 200% 缩放支持。
- **认证继续采用最小非独占共存**：复用现有 provider，只管理 Observer 认证且明确
  支持的生成/计数/目录操作。清理开发候选中的全局模型守卫、拒绝码、路径分类表、
  专属 WebSocket 测试框架及已无调用方的辅助函数，不新增替代抽象或依赖。
  该候选守卫未在 v0.8.0 发布；本版不把它作为正式版行为要求。

## 认证与权限边界

- CPA 原生 Key 和 CPA 签发的 Realtime `ek_…` 继续由 CPA 管理，不自动导入或记账。
  Observer 不读取/复制宿主令牌存储，不新增令牌签发系统，不改变 CPA 核心或请求。
- Observer 自有生成保留精确请求模型授权、额度、并发与记账；count 校验状态和模型，
  但不消耗生成额度、并发或采集。空 `AllowedModels` 仅表示支持接口内不限制模型。
- 图片/音频/视频、Alpha Search、Live/Realtime、WebSocket 等未纳管入口不向
  Observer Key 通用开放；原生 CPA 流量仍保留宿主行为。没有原生凭据兜底时，
  不支持的 Observer 请求在认证阶段被拒绝，而不是执行后漏记账。
- 管理认证签发的目录能力仍是单次、30 秒、仅 `GET /v1/models`，不能推理或管理。
- 请为 CPA 与 Observer 使用不同密钥并发送一套一致凭据。重复明文或混合 query/header
  由宿主认证顺序决定归属；Observer 禁用/删除不能撤销独立的 CPA 原生凭据。
- 仍不保证无原生 Key 的匿名配置透明兼容，也不宣称独立插件是全路由强制网关。
  详细接口范围和宿主限制见 [认证与模型权限](model-policy.md)。

## 升级、回退与明文风险

1. **先停流，等待活跃/待记账归零，正常停止 CPA，然后一致备份整个数据目录和匹配
   的旧插件二进制。** 不在线普通复制正在写入的数据库；繁忙热替换无法补回宿主
   尚未交付的非持久化用量事件。
2. 默认路径仍为 `data/cliproxyapi-observer-v2.db`，schema2 的认证、固定费用、累计
   和历史引用继续保留。功能标记升到 `observer_features=2`，v0.8 feature1 writer
   会拒绝直接打开。回退必须恢复升级前一致备份及匹配旧二进制。
3. **旧 hash-only Key 无法恢复明文**，仍可正常认证；界面明确提示“未保存明文，
   请重新生成”。轮换前请安排客户端更新。也可自行停流备份后新建数据库并重建 Key，
   但发布不会自动删除、覆盖生产数据库或配置。
4. **数据库和备份现在包含可用客户端明文**，仅向可信内部管理人员开放。
   管理 API 仍需管理认证；客户端 Key 不写浏览器持久存储、URL 或日志。
   “记住管理登录”仍是单独、显式的存储选择，不与客户端密钥混淆。

SDK 仍锁定 **CPA v8.0.30 / 插件 schema 6**，未增加依赖或侵入宿主。
界面已嵌入原生库；运行不需要 Node/npm/CDN。发行平台仍为 Linux amd64、
Linux arm64、macOS arm64；Linux 不适用于 musl/Alpine。
下载后核对 `checksums.txt` 和归档内 `metadata.json`。发布不等于生产部署。
