# Observer v1.1.4 发布说明

## 修复 UI 路由重复注册告警

- 修复启动或配置热更新时，Observer 的管理路由与资源路由出现
  `conflicts with a higher-priority plugin and was skipped` 告警的问题。
- 原因是 Observer 同时声明 `/ui` 与 `/ui/`，而 CPA 注册路由时会去掉末尾斜线，
  导致同一插件的两条声明归一化后冲突，并非必须存在另一个插件。
- 现在只注册规范入口 `/ui`；保留 Observer 菜单、`/ui.js`、`/ui.css`、
  `/theme.js` 及现有管理认证边界。插件处理器仍兼容宿主转发的 `/ui/`，
  但不把它声明为独立宿主路由。
- 路由单测按 CPA 的归一化规则检查唯一性；真实宿主替换测试检查启动和配置热更新后
  两个命名空间的 UI 资源可用，且不再出现 Observer 路由冲突告警。

## 依赖与升级边界

- 保留 v1.1.2、v1.1.3 已发布的依赖更新，SDK 锁定 **CLIProxyAPI/v8 v8.0.58**。
  最低宿主仍为 CPA **v8.0.30 / 插件 schema 6**。
- 本版继续使用 **schema3 / `observer_features=4`**，从 v1.1.0–v1.1.3
  升级无需重建数据库；不重算历史费用，不改变 Key 权限、额度、并发或计费行为。
- 不修改 CPA 核心、原生凭据行为、请求正文/头、模型路由、重试或会话。
- 升级前请停流、正常停止 CPA，并备份整个数据目录及匹配的旧插件二进制；
  数据库含客户端密钥明文，应按凭据资料保护。升级后刷新管理页面。
- 从更早版本升级或回退时，仍须遵守 [v1.1.0 发布说明](release-notes-v1.1.0.md)
  中的数据库兼容与一致备份要求。发布不等于生产部署，不会自动修改配置或数据库。
