# Observer v1.0.0 发布说明

## 本版重点

- **完整可解释定价**：独立支持 models.dev v1/v2（默认 v2）、显式映射和完整
  `(model, provider)` 人工价；`base/overrides/multipliers` 可表达覆盖、时段与倍率。
- **真实零价**：目录缺价不阻断推理，按零价记账；不再产生“未计价/补齐价格”状态。
- **精确金额**：单价与账单均为整数 micro-USD（1 USD = 1,000,000 micro-USD），
  缓存读写、reasoning 子集与 TTL 写价分别核算，最终只向上取整一次。
  报价在入库时固定，之后改价、刷新目录或修改映射都不重算历史。
- **请求与分组**：账户名称来自 CPA 只读元数据；Key × 模型按完整身份独立分组。
  缓存命中率以百分数显示两位小数，未知数据不伪装成 0。
- **浏览器本地时间**：列表、详情、趋势、Key 到期与设置时间统一按当前浏览器时区
  显示；今天、近 7/30 天和自定义日期按本地日历筛选，历史汇总亦按当地日界归属。
  支持夏令时和非整小时时差，不改变 UTC 存储。定价规则保留自身时区与计费语义，
  UTC 日期条件额外显示本地生效边界。
- **认证共存**：Observer Key 与 CPA 原生凭据非独占共存；Observer 只管理自己支持的调用。

## 不兼容与升级

本版使用 **schema3 / `observer_features=3`**。旧 schema2（及更早）数据库会被明确
拒绝且不就地改写，不提供自动迁移、双读或自动补价。请先停流并备份整个数据目录；
如需继续使用，请由你安排新的数据库路径并重新创建 Key 与价格配置。
升级过程不会自动删除、覆盖或修改生产数据库。Key 明文仍保存在本机数据库中，
请按敏感凭据管理备份与访问权限。

本地历史日期查询需要更细的长期 UTC 分钟汇总，会增加数据库空间；它不受正文预算
限制，也不会延长原始请求明细或采集内容的保留期。
