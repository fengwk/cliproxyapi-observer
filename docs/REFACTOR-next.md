# Observer 下一版重构方案

> 状态：保留本轮重构的需求与验收设计；实现已完成，当前行为见 [重构说明](reconstruction.md)。
> 基线：v0.7.0，`37a2468f055c698158e50cde9b1758a8417e487e`。
> 用户已另行授权 Review 后提交、推送、发布 v0.8.0 与清理本地工作区；不修改 CPA 或部署生产。
> 本文件保留设计时的阶段性限制；本版升级与兼容性以 [发布说明](release-notes-v0.8.0.md) 为准。

## 1. 目标与约束

目标：做一个看起来属于 CPA、信息完整、操作直接、状态可信的独立插件。不是换一套前端框架，也不是重写 CPA。

### 1.1 需求与阻断性缺陷

| ID | 用户需求 | 本方案的确定决策 | 验收编号 |
|---|---|---|---|
| R01 | 页面铺满可用宽度 | 主页面全宽，仅登录框和弹窗限宽 | A01 |
| R02 | 记住管理登录 | 明示“记住登录”，验证成功后保存插件自己的管理凭据 | A02 |
| R03 | 刷新不抖动、不全局轮询 | 只轮询请求日志；保留旧数据原位更新 | A03 |
| R04 | 日期简洁且对齐 | 两个日期框等高；用户选择的结束日包含在范围内 | A04 |
| R05 | 平铺筛选、统一选择框、明确查询 | 草稿与已应用条件分开，只有查询提交才改变筛选 | A05 |
| R06 | 恢复日志指标和分组 | 完整 Token/缓存/时延指标，模型、Key、账户、提供商分组 | A06 |

### 1.2 不可越过的边界

- 只修改 Observer 仓库及其自有数据、管理 API 和内嵌前端；SDK 继续以已验证的 CPA v8.0.30 为能力基线。
- 仅使用现有原生插件扩展点：客户端认证/准入、请求只读副本、用量事件、管理路由和资源路由。
- 不修改 CPA 核心，不替换宿主页面，不注入脚本修改父页面，不读取宿主登录存储。
- 不改变实际请求正文、请求头、模型 ID、模型选择、重试、会话或提供商路由。价格映射只影响记账身份。
- 模型目录仍通过既有受限能力访问只读 `/v1/models`；不获取凭据文件，不新增通用宿主 HTTP 代理。
- 不访问生产配置、生产数据库或真实密钥。开发和验证只用临时数据库、假密钥和本地模拟上游。
- 客户端密钥只存 SHA-256 哈希；不保存授权头、Cookie、上游密钥、失败响应正文。请求内容默认不采集。
- 金额仍以整数 micro-USD 入库固定；不查询时重定价，不刷新历史成本，不重置已用额度。
- 记账失败阻止受影响 Key 的后续准入，不中断已接受请求；诊断内容可以有界丢弃，金额不可以按此策略丢弃。

### 1.3 KISS：明确不做

不新增 Redux、查询框架、ORM、组件大套件、图表大库、CSS 框架、WebSocket、后台任务平台、独立前端服务或 CDN。继续使用 React 18、TypeScript、现有 Radix 和 Go/bbolt。

不增加第四个主页面，不做可配置仪表盘、任意 SQL/分组构建器、全局时区系统、任意 Header 透传、二进制/响应正文归档或客户端密钥保险库。

不为了“匹配更多”去删模型版本、随意转小写、删除 `:free` 或取第一个同名报价。

### 1.4 认证边界：优先于 UI 的 P0 门槛

已确认当前版本注册 `frontend_auth_provider_exclusive=true`，会将 CPA 原有 API Key provider 从客户端认证链中排除。管理中心系统页用服务器保存的第一条 API Key 请求实际的 `/v1/models`，因此会被返回 401。它不是管理密码失效，也不是必须更换为 Observer Key 的正常要求。

第二处越界是 before 对未知 caller_scope 直接 401。只取消独占仍会阻止已经通过 CPA 自身认证的推理请求。两处必须一起修，不能加一个 `/models` 特判了事。

**确定的行为：**

- Observer 不再声明全局独占认证，不因自身存储失败重新占据全站认证。
- 原有 CPA Key 和其他插件的认证链保留；原生 Key 按原逻辑工作，不被默认为 Observer 管理 Key。不能把“未匹配 Observer Key”解释为全站认证失败。
- 前端认证先按 Method + 原始 URL Path 分类。只有受支持的模型执行和明确的目录/计数辅助操作可以识别 Observer Key；其他路径返回未处理，由宿主原链决定，不返回“所有请求认证成功”。
- 执行管控必须同时满足“明确的模型生成操作”与“归属于本插件已经验证的 Key”。未知/其他 caller_scope 直接返回空拦截响应，不访问本插件额度/正文存储，更不能因 Observer store 故障阻断无关流量。
- 故障恢复/异常捕获的 fail-closed 边界放在确认归属之后；不能保留“任何 before 异常都全局拒绝”的兜底。归属恢复和 native 替换竞态必须有测试。
- 已识别的 Observer 模型调用仍然 fail-closed：无效/停用/删除/过期 Key、额度/并发/存储问题按原约定拒绝。归属不能从正文中是否有 `model` 猜测；不能仅靠 Generate 标记判断，因为当前 SDK 的 count_tokens 也可能标为 true。
- 对已确认的 HTTP 模型执行族使用有限白名单：chat/completions、completions、messages、responses 及 Codex responses 别名、Gemini generateContent/streamGenerateContent；图像/语音/视频等端点只有在同一 SDK 的计量和生命周期原生验证后才列为支持。未验证的操作不接管原生 Key 的行为，也不对外宣称支持。
- 目录 GET `/v1/models`、模型详情、Gemini 目录，计数 POST `messages/count_tokens`/Gemini countTokens：不扣额度、不占并发、不采集正文、不按模型生成拒绝。可以按合法 Observer Key 提供有限的辅助认证，不能替换响应或放开未知凭据。
- 管理 API、插件资源、健康检查、OAuth、文件/异步任务查询、会话管理等继续各自的 CPA 认证/处理；不进入 Observer 生成准入。
- 用量/完成事件仍验证本插件归属，只操作自己的 Key。原生 Key 的调用不假装受到 Observer 配额控制；请求页说明“当前统计为 Observer 管理 Key”。
- 私有只读目录 capability 仅服务插件自己的模型发现，不再成为所有 CPA 用户访问目录的唯一通道。

**真实 SDK 限制，不用隐式放权绕过：**

1. 非独占 provider 只有“认证成功/未处理”，没有按路径注册认证或替宿主验证 Key 的原生接口。不读取宿主密钥列表、不改注册顺序来抢认证。
2. CPA 未配置任何原生 API Key 时，其原始匿名目录与“安装任意前端认证 provider 后全部弃权则 401”的行为不同。取消独占本身不能解决这一情况。本次共存兼容基线要求 CPA 已有原生认证 Key；不能承诺无 Key 匿名模式的严格透明性。若它也必须支持，这是 SDK 兼容门槛，不能靠一律返回认证成功实现。
3. 同一密钥不得同时作为 CPA 原生 Key 与 Observer 管理 Key，否则实际认证归属取决于宿主 provider 链，无法保证 Observer 配额；不通过窥探宿主配置自动排查。明确提示管理 Key 必须独立，不宣称能接管原生 Key。

隔离 native 复现（同一个有效的假 CPA 原生 Key）：

| 请求 | 停用 Observer | v0.7 原样 | 临时副本仅取消独占 |
|---|---|---|---|
| `GET /v1/models` | 200 | 401 | 200 |
| `GET /v1beta/models` | 200 | 401 | 200 |
| `POST /v1/chat/completions` | 200 | 401 | 401 |
| `GET /healthz` | 200 | 200 | 200 |

这只是缺陷复现，不是修复验收。**CPA 自身已认证请求能继续工作，同时无效请求仍被原认证拒绝**，是后续所有 UI/统计改动的前置门槛。

## 2. 页面结构与视觉规范

### 2.1 信息架构

```text
Observer
├─ 请求日志（默认）
│  ├─ 平铺查询条件
│  ├─ 区间概览 + 请求/失败趋势
│  ├─ 请求明细
│  ├─ 模型分组 / Key 分组 / 账户分组 / 提供商分组
│  └─ 请求详情：概览 / 请求头 / 请求体
├─ Key 管理
│  ├─ 名称搜索 + 状态筛选 + 创建 Key
│  └─ 编辑 / 启停 / 轮换 / 重置 / 恢复核算 / 删除
└─ 设置
   ├─ 请求内容与保留
   ├─ 模型价格
   └─ 存储维护
```

设置使用三段清晰分区及页内定位，不另造一层侧边栏。价格表分页，诊断不堆进主操作区；异常摘要始终可见。

### 2.2 整体风格

设计方向：CPA 原生感、克制、清晰、适度紧凑。靠排版、对齐、留白和信息层级形成品质，不靠彩色大卡片、渐变或大量阴影。

| 项目 | 规范 |
|---|---|
| 内容宽度 | 主内容 `width:100%; min-width:0`，去掉 1440/1100px 居中上限；对 iframe 的可用内容区负责，不覆盖宿主侧栏 |
| 页边距 | 宽屏 24px、常规 16px、窄屏 12px；断点按 iframe 内容宽度，不按父窗口猜测 |
| 间距 | 4/8/12/16/24/32px；分区 24px，区内 16px，字段间 12px |
| 字体 | 系统字体，不加载远程字体；正文/表单 14px，表格/辅助文字 13px，分区标题 16px，页标题 20px |
| 数值 | 概览数值 24px/600；金额、Token、时间使用等宽数字；完整 ID/JSON 使用等宽字体 |
| 控件 | 桌面按钮、输入框、选择器统一 36px；窄屏主要触控目标至少 44px；多行输入另定高度 |
| 圆角 | 控件 8px，分区/弹窗 12px；不把所有东西做成胶囊 |
| 表格 | 表头 40px，双行数据行至少 56px；数字右对齐，文字左对齐；行 hover 轻量，斑马纹非必要不加 |
| 表面 | 背景/容器/浮层使用 CPA 语义 token；表格直接放在分区内，不套多层卡片 |
| 操作 | 每个任务区一个主操作；普通操作中性；危险操作只在相应菜单/确认框强调 |
| 动效 | hover/focus 120–160ms，不做数据行进出动画；遵循 reduced-motion |

暖灰浅色、纯白、深色均在登录前正确初始化。嵌入时继承宿主主题；独立打开时使用系统主题及插件自己的选择，不修改父页面。

**对比度优先于机械照抄 token。** 已检查的宿主主色 `#8b8680` 配白字对比度约 3.61:1，不适合普通大小按钮文字。Observer 使用局部高对比中性操作色：从宿主前景/背景配对派生，不改宿主变量、不另起蓝紫品牌色。普通文字至少 4.5:1，大字与控件边界至少 3:1；重要辅助信息不使用过淡的 tertiary 色。

状态使用“文字 + 图形/标签”，不能只靠红绿；成功色不铺满整行。警告只用于需要注意的状态，不能因为曾经丢过一个正文就永久把系统标成计费故障。

### 2.4 通用交互与小屏

- 枚举输入统一使用同一套选择器；长列表可搜索，短列表无需多余搜索框。搜索是查找选项，不是执行请求日志查询。
- 标签、控件高度、下拉浮层、错误行、聚焦态一致；不混用原生 datalist、裸 select 和另一套自制选择器。
- 字段帮助说明不挤进某个输入框上方；筛选区错误集中在该字段下方，正常状态各控件基线一致。
- 宽表只在表格容器横向滚动；不让整个页面横向溢出，不在小屏隐藏 Token/缓存/费用列。首列可固定，不能遮住其他列。
- 长模型名允许两行及查看完整值；不能靠无限加宽列，也不能只留无法辨认的省略号。
- Dialog 继续复用 Radix。普通编辑宽约 640px，复杂 Key 编辑约 760px，请求详情约 960px；均受 iframe 可用尺寸约束，小屏接近全屏。标题、关闭和底部操作始终可达，内部单一纵向滚动。
- 弹窗有键盘焦点约束、Escape、焦点返回；提交中不重复发送，服务端成功后才更新状态。危险确认默认聚焦取消，不要求为每个普通操作输入一段文字。
- 错误、空结果、初次加载、后台更新、旧数据过期分别设计；复制失败提供可手工选取的内容，不假报成功。

## 3. 查询与刷新：一份已应用条件，一次更新视图

### 3.1 筛选语义

`draftFilters` 只用于表单，`appliedQuery` 只用于请求。修改任一字段、快捷日期或重置，只改草稿；点击查询或 Enter 后校验、应用并回到第一页。不能在 blur/change 时偷偷查询。

日期均按 UTC，两个框显示具体日期且默认今天。开始日包含、结束日也包含；后台统一转换为 `[开始日 00:00, 结束日次日 00:00)`，截止当前日时使用本次服务端查询时间。删除原先的长提示和“结束日不含”交互。

自动刷新“今天”等动态范围时推进截止时间；固定历史结束日不被偷偷改成今天。无效日期保留草稿与上一次成功结果，在原处给出可修正错误。

选择器来源是可用模型目录与保留期内的元数据索引，不是当前页的 25 条记录。不读取凭据文件。删除/下线的 Key 和模型仍可用于历史查询，并明确标注。

### 3.2 刷新规则

- 刷新选择放在请求页，默认 5 秒，可选关闭/5/10/30 秒；不再从 App 给三个页面传全局刷新周期。
- 只在请求页可见、第一页、无未应用条件、无详情/对话框时自动刷新；历史分页和固定历史区间默认暂停并说明原因。
- 分组视图与请求明细共用本页的刷新条件，不生成第二个计时器。
- Key 管理在进入页、手动刷新、操作成功后更新；设置在进入页、手动刷新、保存/同步/维护操作后更新。两者没有常驻计时器。
- 任意时刻最多一个请求视图加载。取消旧请求，并用查询序号拒绝迟到响应；401 统一结束登录并取消全部在途请求。
- 初次加载用占位；后台刷新保留现有表格、图表和概览，只更新数据。按钮和状态区域预留宽度，不改变高度。
- 保留滚动位置、表格横向位置、焦点、选中文字和当前展开状态。用户在表格内阅读/选择文字时暂停自动替换，手动刷新仍可用。
- 无数据变化时不替换行、不触发布局动画；新请求按稳定 ID 更新。详情只在打开时读取，不随轮询重复下载正文。
- 刷新失败保留旧结果，显示最近成功时间与非阻塞错误。失败退避最长 60 秒，不每轮弹 toast；手动刷新可立即重试。
- 脏表单切主页面先确认；退出或 401 清理详情、未保存密钥与请求缓存，不把敏感草稿保存到浏览器。

## 4. 日志指标、分组与统计口径

### 4.1 默认可见信息

请求表列：时间/模型、客户端 Key、提供商/账户、状态、未缓存输入/输出、缓存读/写、缓存命中率、耗时/TTFT、TPS、费用、请求内容/查看。

Token 使用紧凑数字展示，完整整数可直接查看；费用最多六位小数，非零小额不四舍五入成 `$0.00`。未定价与明确免费分开显示。Key 使用名称，内部 ID 只作为次要信息；账户默认显示安全的 AuthIndex，不冒充已经获取了账户昵称。

详情概览完整展示计量类别、原始 Usage、口径质量、固定费用、当时的定价来源与匹配信息。推理 Token 是输出子集，不能再次计入总输出或重复计费。

### 4.2 明确公式

```text
完整输入 = 未缓存输入 + 缓存读 + 缓存写
缓存命中率（Token）= Σ完整口径缓存读 / Σ完整口径完整输入
失败率 = 失败请求 / 请求数
平均耗时 = 有效耗时总和 / 有效耗时样本数
平均 TTFT = 有效 TTFT 总和 / 有效 TTFT 样本数
单条 TPS = 输出 Token / ((总耗时 - TTFT) / 1000)
```

TPS 只在流式、Token 口径完整且 `0 < TTFT < 总耗时` 时展示。分母为零或样本未知显示 `—`，不是 0。缓存率先累计分子分母再相除，不平均各请求的百分比；未知口径不混入分母，展示样本覆盖数。

总 Token 保留 SDK 归一化的权威值；未知分类时保留原始 Usage，不把零填充字段伪装成“未使用缓存”。

### 4.3 分组与读取

模型按“完整模型 ID + 提供商”分组；Key 按稳定内部 ID；账户按 AuthIndex；提供商按真实用量事件中的 Provider。未知维度显式分到“未归属”。

概览、趋势和当前分组使用同一套已应用条件，覆盖整个查询区间，不是当前页。请求默认时间倒序，分组默认请求数倒序并以完整维度稳定打破平局；首版不做任意排序/自定义分组。

新增一个窄职责的 `GET /requests/view`：一次只读事务返回本次范围、概览、趋势和当前视图分页。前端收到完整成功结果再一次更新，避免三套加载状态和互相打架的数字。旧 `/requests`、`/summary` 保留并复用同一查询实现，不维持第二套业务口径。

查询使用一致的数据库只读事务；生命周期读写锁保护句柄，短时复制所需配置后不长持准入/记账的状态互斥锁。关闭/替换句柄等待读事务结束，统一锁顺序，不能边复制旧快照边接受写入后直接替换丢失新账目。

### 4.4 长期汇总与旧数据

- 保留已有日汇总的请求/失败/总 Token/费用，增加细分 Token、完整口径样本、延迟/TTFT 总和与样本数、未定价计数。
- 使用同一组现有维度；新增有限的小时汇总，保留期跟随原始明细。日汇总仍负责长期历史，不为四种分组各建一套统计。
- 新用量在现有记账事务内同时更新汇总；去重、失败回滚、原报价重试保持不变。
- 只对仍保留的原始明细回填新增统计，不计算新费用；已存在的基础总数不再次累加。
- 回填有版本标记与分批检查点，与新写入使用同一幂等规则；崩溃/重试不能重计。未完成时显示“统计补全中”，不用局部结果冒充全量。
- 过期且只剩旧四项汇总的历史，细分数据不可恢复。返回 coverage/缺失字段；旧总额照常可见，缺失指标显示“该历史区间未保存”，不是零。
- 完整小时/整日从汇总读取，只有保留期内的边界片段读取明细；不每五秒扫描解压全部历史记录。超出明细保留期无法支持的精细时间边界明确拒绝，并提供整日范围修正。

## 5. 请求头/体的完整生命周期

### 5.1 最小配置

设置只提供以下核心项，正常配置不藏进“更多存储限制”：

| 项目 | 设计 |
|---|---|
| 新请求采集范围 | 不保存内容（默认）/仅安全请求头/安全请求头与 JSON 正文 |
| 元数据保留 | 沿用现有 1..168 小时与当前已保存值 |
| 请求内容保留 | 独立配置 1 分钟至元数据保留期；新安装默认 24 小时且不超过元数据保留期 |
| 统计保留 | 沿用现有 1..3650 天 |
| 单条正文上限 | 沿用 1B..8MiB；新安装默认 1MiB |
| 内容存储上限 | 沿用 1B..1GiB；新安装默认 256MiB，明确为压缩后内容预算而非数据库总大小 |

三个保留期允许用可读单位输入，但统一整数存储与校验；容量切换单位不损失字节精度。不恢复旧版更大的上限，除非另有内存/磁盘证据支持。

升级时采集范围继承原开关：关闭→不保存，开启→安全头与 JSON；内容保留期首次继承原元数据保留期，不静默扩大既有保存范围。之后降低元数据保留期时，界面同步提示并校验内容期不能更长。

### 5.2 采集与安全

采集对象只限被 Observer 接受的生成请求的客户端入站副本。不是上游发送实录，不记录响应体，也不是所有 CPA 流量。

请求头采集范围为认证前客户端入站副本，不是上游发送实录。除 Authorization/Proxy-Authorization、Cookie/Set-Cookie、API Key、Token、Secret/Password/Credential/Private Key 及认证相关头外，其余头名称与多值均保留，字段名大小写不敏感。敏感头整体省略，不复制原值、不落盘；不得采集上游请求头或上游凭据。头名称与保留值累计受 16KiB 上限约束，越界丢弃整组头并标记 `headers_too_large`，仅被排除的敏感头不占预算。URL 用户信息与敏感查询参数继续脱敏。UI 明示范围。

入站副本进行大小限制、JSON 校验、敏感字段与 URL 查询凭据脱敏，再异步 gzip 入库。修正正文中 `max_tokens` 等正常参数被宽泛 `token` 规则误伤的问题；不能为此放松真正秘密字段的脱敏。所有处理只作用于副本。

正文超限整份不保存，不存可能泄密或无法解析的截断前缀；安全头仍可独立保留。非 JSON 首版明确“不支持此正文格式”，不伪装为“已脱敏”。

有界队列与非阻塞采集保留；采集锁竞争、队列满、正文过大、格式不支持、容量淘汰、写入失败分开统计。能关联到记录的返回具体原因；无法关联时返回未确认原因和全局分类计数，不声称每次丢弃都可逐条追溯。

### 5.3 状态、压缩、过期与容量

- 详情返回 `headers_status`、`body_status`、原因码、采集/到期时间、原始/压缩后字节数；元数据列表只含小型状态字段，不含头部值与正文。
- 正文状态至少区分：可用、已脱敏、未开启、采集中、过大未保存、不支持格式、已过期、容量淘汰、手动清除、未捕获/原因未知。头部独立判断，不因正文不可用而一并隐藏。
- “已脱敏”表示仍有可读取的脱敏内容，不再用它表示解析失败。`truncated` 旧值显示“超限未保存”，不假装有部分正文。
- 保留 gzip，不引入算法选择。新增内容信封有版本与明确尺寸；避免新增重复压缩层，旧格式可读，不做全库重压。
- 到期在读时立即生效，不依赖一分钟清理。保存内容时记录原到期时间；当前策略更短时取更早期限，延长策略不复活原已过期内容。
- 使用采集时间有序索引进行 FIFO，压缩后占用计数与写入/淘汰同事务更新；不用 Key/Trace 的字典序冒充时间。
- 先清理过期、再淘汰最旧内容，为新内容腾出预算；单条压缩对象比整个预算还大时拒绝该条并标原因。不每条遍历整个 bucket 统计大小。
- 关闭采集停止新内容，旧内容仍按到期策略保存且不等于已经删除。延续当前隐私边界：off 不返回历史内容，headers 不返回历史正文；界面明确当前查看范围与清空入口，范围收窄时清理前端详情缓存。关闭时排队任务二次校验，不再新增持久化内容。

### 5.4 三种维护操作

| 操作 | 确认与结果 | 不允许影响 |
|---|---|---|
| 清理已过期内容 | 立即逻辑删除过期头/体，返回条数与内容字节 | 未过期内容、元数据、汇总、费用与额度 |
| 清空已保存请求内容 | 破坏性确认，说明不可恢复且不等于磁盘安全擦除 | 用量日志与 Key 累计 |
| 回收数据库空间 | 单独确认临时空间和维护影响，显示文件前后大小 | 所有有效账目和未清理内容 |

清空操作推进采集代次，拒绝操作前排队内容重新写回；不因 worker 延迟导致刚清空的内容“复活”。新请求是否继续采集由当前模式决定。

后台每分钟清理过期项；成功/失败、最近执行时间、清理数量可见，不能丢弃返回错误。手动清理只处理请求内容；原始元数据和日汇总仍按各自保留期后台清理。

物理整理继续使用 bbolt 安全副本、同步、原子替换与失败保留原句柄，不做并发写入快照的无损热替换承诺。仅在没有活跃请求、待记账和待落盘写入时进入短时维护窗口；有活动时返回可重试的 busy。

维护窗口内拒绝新的生成准入（503，可重试），管理写操作返回 busy；不取消已接受请求，也不修改 CPA 重试。自动整理只在空闲、空闲页大于 16MiB 且超过文件 25%、距离上次尝试至少 15 分钟时机会性执行；不满足就跳过。不能把维护期间的拒绝或采集丢弃标成“容量不足”。

存储页显示内容占用/预算、数据库大小、估算可回收空间、最近清理/整理结果；估算与实测明确区分。历史丢弃累计标明统计起点，与当前计费故障分别展示。

## 6. Key 管理与管理登录

### 6.1 客户端 Key 的身份与操作

内部 ID 稳定、用于账目关联；客户端密钥才用于调用。表格以名称为主，次要位置可明确“复制内部 ID”，绝不把它简称“复制 Key”。

自动密钥使用密码学安全随机源及无偏采样，生成 `sk-` + 48 位 `[A-Za-z0-9]`，总长 51；内部 ID 不随之改格式。既有密钥仍有效。

创建/轮换采用“填写→服务端成功→一次性密钥展示”的流程。成功页说明“关闭后不能再次查看”，提供显示/隐藏、复制与手工选择；关闭、离开或 401 清空内存。不自动写入剪贴板，不写 localStorage/sessionStorage/日志/URL。自定义值继续严格 8..256 可见 ASCII，不 trim；短值提示风险但不额外改变已约定的合法范围。

创建/编辑沿用一个表单：名称、密钥生成方式（仅创建）、并发、有效期、模型权限、四种额度。不限是明确选项，不靠用户理解 0。编辑未修改到期时间时保留原 RFC3339 精度。

### 6.2 明确生命周期

| 操作/状态 | 密钥是否有效 | 能否恢复 | 历史 |
|---|---|---|---|
| 停用 | 否，哈希保留 | 启用即可 | 不变 |
| 撤销（兼容已有 API） | 否，哈希清除 | 必须先轮换，再明确启用 | 不变 |
| 删除 | 否，清除认证索引并标记 deleted_at | 终态，不能直接启用/轮换 | 保留最小账目引用 |

新增 `POST /keys/delete?id=...`，不把旧 `DELETE /keys` 从“撤销”悄悄改成其他语义。删除确认显示名称、作用和历史保留说明。默认管理列表不显示已删除项；历史过滤器仍能定位它，并标注“已删除”。

删除采用最小墓碑，不物理删除记账关联行。活跃请求或待记账时返回 busy，不杀请求、不丢账；重复删除幂等。已删除 Key 禁止修改、启用、轮换、重置和核算恢复。既有仅清空哈希的记录识别为“已撤销”，不是普通停用。

额度重置必须选择窗口并说明影响；核算恢复保持责任确认，不能用启用按钮绕过记账失败阻断。

### 6.3 记住管理登录

登录框明确显示“记住登录（仅限可信设备）”，默认勾选，用户提交即确认该选择；只在管理认证成功后保存插件自己的管理密钥。

- 勾选：写插件命名空间的 localStorage；未勾选：仅标签页 sessionStorage/内存。切换方式清理另一处副本。
- 应用恢复时只验证一次；通过后进入页面，不反复要求登录。存储被禁用时回退并明确提示，不能宣称已记住。
- 退出或确切 401 清理两处存储、内存、详情和全部在途请求；不因网络超时擅自删除有效凭据。
- 不读取 CPA 自己的 localStorage、Cookie 或自动复用宿主凭据；同源并不意味着可窥探其他应用存储。
- 浏览器存储不是保险库；同源脚本/XSS 可能读取。不给固定前端加密制造虚假的安全感。
- 这是对 v0.7“仅会话”和 AGENTS“不得持久化浏览器凭据”的**窄例外**：仅用户明确记住的管理登录。实现时必须同步规则及安全文案，客户端密钥与采集授权头仍绝不持久化。

## 7. 模型价格：匹配可靠、来源可解释

### 7.1 界面

设置页先显示目录状态：自动定价开关、最近成功同步、可用条目数、CPA 可用模型数、已匹配/冲突/未收录数量。同步失败保留最后有效目录，明确“使用旧目录”，不把失败变成全部免费。

价格表按模型搜索、按匹配状态筛选，默认每页 25 条；列为模型、报价渠道/目录模型、输入/输出、缓存读/写、来源与原因、操作。未提供费率显示 `—`，明确零价显示 0。

常用操作只有“选择报价来源”和“手动覆盖”。选择报价来源是价格映射，不改变请求路由。冲突时展示候选，不要求用户手写 Provider；未知模型允许手动价，明确只影响未来记录。

条件规则保留现有功能和顺序，初次无规则时保持简洁；编辑时解释完整输入阈值与 UTC 时段。不把规则基价预览冒充实际请求费用。

### 7.2 一个 resolver，同一套报价

保留“首条条件规则 > 完整模型手动价 > 自动目录 > 缺价 $0”的业务优先级。预览和记账调用同一身份解析器，预览不伪造 Token、不写观察记录、不触发网络。

自动解析顺序：

1. 管理员为完整公开模型指定的目录映射；
2. 可信的真实 Provider 对应关系与精确目录 ID；
3. 经核实的公开命名空间解析，例如 `opencode-go/hy3` → provider `opencode-go`、model `hy3`；`commandcode/` 只去掉该已知外层，保留内部 `moonshotai/...` 等 ID；
4. 目录提供的明确 canonical 身份关系；
5. 无渠道时仅接受唯一/完整费率一致的精确身份；其他情况返回冲突或未收录。

不同可信线索指向不同条目时返回冲突，不私自选择。`owned_by` 不是计费渠道；不直接拿它填 Provider。保留模型大小写、日期、版本和 `:free`；新命名空间需证据与回归用例，不做通用“删第一个斜杠”。

返回匹配类别、目录 Provider/Model、映射依据、目录时间、候选与缺失费率。保留 `source=manual/auto/unpriced` 的旧语义，新增 reason 区分自动关闭、目录不可用、无匹配、多渠道冲突、缺必需费率。

目录中的“缺字段”与“明确 0”分开建模；有实际非零用量却缺必需费率时，依既有缺价政策明确按 $0 并记原因，不默默编造费率。不能把目录里未支持的上下文分档当成适用于所有上下文的平价；可解析的分档与现有完整输入规则共用判断，不能表达的明确标注并提供人工覆盖。

实际用量有可信 Provider，而模型预览没有时，二者可以得到不同结果；预览必须说明渠道信息缺失，不承诺裸模型唯一价。明确映射后，同身份/同用量的预览诊断与记账必须一致。目录报价不是上游真实账单保证。

## 8. 实现边界与接口契约

### 8.1 模块职责

```text
CPA 已有 SDK 扩展点（不改）
        │
Observer plugin：注册、认证路由、只读事件适配、生命周期
        ├─ engine：准入/固定记账、有限统计查询、内容生命周期、维护
        ├─ pricing：目录/身份解析/不可变报价（报价时不联网）
        └─ web：Shell + 三页 + 小型共享控件/格式化/API 客户端
```

App 只负责登录、导航、主题、安全视口和未保存确认，不负责三个页面的加载编排。请求页拥有一份查询状态和一个计时器；设置每个分区拥有独立草稿与保存状态，保存一个分区不夹带另一区未保存内容。

不新增通用 Repository/Service 层套娃。可以在现有包内按 query/statistics/capture/maintenance/resolver 职责拆文件，不把所有功能继续塞入页面单文件。

### 8.2 最小 API 变化

以下路径均相对插件管理前缀，使用精确静态路由；ID 继续走查询参数。全部由 CPA 管理认证保护，资源路由仍只提供固定前端文件。

| 接口 | 变化/职责 |
|---|---|
| `GET /requests/view` | 新增；date-only 的 `from_date/to_date`、现有身份/状态筛选、`view=requests/model/key/account/provider`、page/page_size；单事务返回当前视图、概览和趋势 |
| `GET /requests/facets` | 新增；按 field、搜索词、cursor、limit 获取有限的模型/Key/账户/Provider 元数据选项；不包含任何凭据值 |
| `GET /requests`、`GET /summary` | 保留现有 RFC3339 范围语义与旧字段；复用统一查询函数，不静默改变旧调用者的结束边界 |
| `GET /requests/detail?id=` | 增加头/体独立状态、原因、时间、尺寸、固定报价的诊断快照；旧字段仍可读 |
| `POST /keys/delete?id=` | 新增终态删除；原 `DELETE /keys` 保持撤销 |
| `GET/PUT /settings` | 增加 capture_mode、内容保留秒数和明确报价映射；保留旧 capture_enabled 兼容输入 |
| `POST /captures/cleanup` | 新增；只清过期内容，返回实际处理条数/字节 |
| `POST /captures/purge` | 新增；请求体确认标志，清空内容并推进采集代次，返回实际结果 |
| `POST /compact`、`GET /health` | 保留；增加维护状态、内容预算、可回收估计、分类丢弃与最近执行结果 |
| `GET /prices`、`POST /prices/preview` | 扩充匹配诊断与候选；preview 保持有界、只读、无网络/持久写 |

请求视图响应固定为：

```text
range {from, to, as_of, timezone:"UTC"}
summary {兼容基础总数 + 细分指标 + 样本覆盖}
series {实际 granularity, buckets}
records[] 或 groups[]（只填当前视图需要的行）
pagination {page, page_size, has_more}
coverage {各类保留起点、缺失指标、回填状态}
```

`as_of` 是本次数据库读取时间，不冒充可跨请求长期复用的快照游标。只返回当前所选分组，不一次装载四套完整分组。page_size 最大 100，默认 25；无任意字段表达式。

新增 `/settings` 的 capture_mode 取 `off/headers/headers_and_body`。旧调用者只发 capture_enabled 时，false→off；true 只在原本关闭时开启 headers_and_body，已经启用时保留当前更窄范围。新调用者同时发两者时必须一致，否则 400。未提交的新增可选字段保留已保存值，不因旧客户端回写丢掉内容保留或价格映射；旧采集状态和模式在后端兼容边界转换，不能在各页各猜一遍。

### 8.3 自有数据兼容与维护

- 直接打开当前 v0.6/v0.7 的 schema2 数据，不迁移旧 v0.5 等异构数据库，不清库。
- 主 schema 保持 2；新增命名空间的 `observer_features=1` 标记与版本化内容/索引，只增量补建，不整库迁移。新实现拒绝高于自身支持的功能版本。旧内容可读，旧 Key ID/哈希/累计/原报价不变。
- 旧 v0.7 不识别新功能标记，不能承诺它会自动拒绝新库，也不支持写入后直接降级；回退只允许恢复升级前一致备份并使用对应旧二进制。升级前备份、失败恢复与拒绝未知新版本需实测，不能宣称任意回滚。
- 墓碑、统计回填、FIFO 计数、代次更新均在既有 bbolt 事务内保证一致，不能靠前端多次请求拼成原子操作。
- 所有新状态、枚举、参数和体积都有服务端校验。错误不回显密钥、正文或原始底层异常中的敏感内容。
